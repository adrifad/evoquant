# SL+ Position Management Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a configurable break-even-plus stop that updates the existing OKX protection for scalp and 15m trades, only moves risk favorably, and keeps local trade state consistent with confirmed exchange responses.

**Architecture:** Store the initial stop separately from the active stop so realized R stays anchored to entry risk. A pure calculator determines whether the current mark price warrants a one-way SL+ move; an OKX algo adapter amends the live SL while retaining TP. A per-trade serialized mutation queue ensures stop amendments and all close paths do not run concurrently. Scalp's 15-second sweep and the main 60-second sweep share the same manager.

**Tech Stack:** TypeScript, Node.js, better-sqlite3, Zod, OKX v5 algo-order REST API, Node test runner.

- [ ] Implement `calculateSlPlusStop` as a pure function. Let `dir = side === "LONG" ? 1 : -1`, `initialRisk = abs(entryPx - initialStopPx)`, and `favorableR = ((markPx - entryPx) * dir) / initialRisk`. Return no candidate below `activation_r`. Otherwise use `lockDistance = max(initialRisk * lock_in_r, entryPx * min_profit_buffer_pct / 100)`, set `candidate = entryPx + dir * lockDistance`, round LONG upward and SHORT downward to `tickSz`, then require the candidate to improve `currentStopPx` and remain at least one tick behind `markPx`.

## Self-review

- Spec coverage: initial stop remains available for R accounting; exchange-side SL remains active and is amended without a cancel gap; deterministic price monitoring remains independent of the LLM; scalp and 15m paths share policy with their existing 15s and 60s monitoring cadences.
- Risk boundary: default activation is +1R, stop locks at least +0.05R or the configured 0.12% entry-price buffer, whichever is greater. Values remain editable in `config/trading.yaml`; this is a gross-price buffer, not a guarantee of net profit after all funding and execution costs.
- No live or demo exchange request is part of tests or implementation verification.
